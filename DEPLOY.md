# Публикация сайта «Малина» в интернете

Инструкция рассчитана на то, что программировать не нужно: только кнопки и копирование.
Всего три части: **GitHub → Render → первые настройки**.

Файлы для хостинга уже готовы: `package.json`, `render.yaml`, `Dockerfile`, проверка
живости `/healthz`, порт и папка данных берутся из настроек хостинга.

---

## Часть 1. Выложить код на GitHub

1. Откройте **GitHub Desktop** (установлен, вход в аккаунт уже выполнен).
2. **File → Add local repository…** (`Ctrl + O`).
3. Укажите папку `C:\Users\user\Desktop\malina` → **Add repository**.
4. Нажмите **Publish repository**.
5. Имя репозитория: например `malina-studio`.
   * **Keep this code private** — оставьте галочку, если код не должен быть публичным.
     Render умеет работать и с закрытыми репозиториями.
6. Нажмите **Publish repository** и дождитесь окончания отправки.

Проверка: в браузере откройте свой репозиторий на github.com — там должны быть
`server.js`, `public/`, `README.md`. Файла `data/db.json` там быть **не должно** —
это личные данные гостей, они исключены намеренно.

---

## Часть 2. Опубликовать сайт на Render

1. Зайдите на **https://render.com** → **Get Started** → **GitHub** (вход через GitHub).
2. Разрешите Render доступ к репозиториям (можно выбрать только нужный репозиторий).
3. В панели Render: **New +** → **Web Service**.
4. Выберите репозиторий `malina-studio` → **Connect**.
5. Заполните поля:

   | Поле | Значение |
   |---|---|
   | Name | `malina-studio` |
   | Region | `Frankfurt (EU Central)` — ближе всего к России |
   | Branch | `main` |
   | Runtime / Language | `Node` |
   | Build Command | `npm install` |
   | Start Command | `npm start` |
   | Instance Type | `Free` (или `Starter`, см. ниже) |
   | Health Check Path | `/healthz` |

6. Раскройте **Environment Variables** и добавьте (для надёжного варианта):

   | Key | Value |
   |---|---|
   | `NODE_VERSION` | `20` |
   | `HOST` | `0.0.0.0` |
   | `DATA_DIR` | `/var/data` |

7. Нажмите **Create Web Service** (или **Deploy Web Service**) и подождите 2–4 минуты,
   пока в логе появится строка про «ФОТОСТУДИЯ МАЛИНА».
8. Сверху появится адрес вида **https://malina-studio.onrender.com** — это ваш сайт.

### ⚠️ Про бесплатный тариф — прочитайте обязательно

| Что | Бесплатный тариф (Free) | Платный тариф (Starter) + диск |
|---|---|---|
| Заявки гостей и фото | **могут обнулиться** при перезапуске, обновлении или простое сервера | сохраняются на постоянном диске |
| Скорость | после 15 минут без посетителей сервер «засыпает», первое открытие 30–60 секунд | работает всегда, открывается сразу |
| Стоимость | 0 | ориентировочно ~7 $/мес + диск около 0.25 $ за ГБ (проверьте актуальные цены на render.com/pricing) |

Для настоящей работы студии важны сохранность заявок и быстрый отклик, поэтому
рекомендую платный тариф с диском:

1. При создании сервиса выберите **Instance Type → Starter**.
2. Ниже нажмите **Add Disk**: Name `malina-data`, Mount Path `/var/data`, Size `1 GB`.
3. Убедитесь, что в переменных окружения есть `DATA_DIR` = `/var/data`.

Если выбрали бесплатный тариф — просто **не добавляйте диск и `DATA_DIR`**,
а заявки дополнительно сохраняйте себе: панель → Настройки → «Скачать резервную копию».

### Вариант в одну кнопку: файл render.yaml

В проекте уже лежит `render.yaml` с готовыми настройками (включая диск и данные).
Чтобы использовать его: в Render выберите **New + → Blueprint**, укажите репозиторий —
Render сам создаст сервис по этому файлу. Для бесплатного тарифа откройте `render.yaml`,
удалите блоки `disk` и `DATA_DIR`, замените `plan: starter` на `plan: free`.

## Часть 3. Первые действия после публикации

1. Откройте `https://ваш-адрес.onrender.com/admin.html`.
2. Войдите: логин `admin`, пароль `malina2024`.
3. **Сразу смените пароль:** Настройки → «Безопасность входа».
4. Замените контакты на свои: Настройки → «Контакты» → **Сохранить всё**.
5. Удалите 8 картинок-заглушек и загрузите настоящие фото: вкладка «Фотографии».
6. Проверьте запись: откройте сайт в режиме гостя и забронируйте тестовое время —
   заявка должна появиться во вкладке «Заявки». После проверки удалите её.

## Часть 4. Свой красивый адрес (домен)

1. Купите домен, например `malina-studio.ru` (регистраторы: reg.ru, nic.ru — примерно
   200–400 ₽ в год за .ru).
2. В Render: ваш сервис → **Settings → Custom Domains → Add Custom Domain** →
   введите домен.
3. Render покажет, какие записи DNS нужно прописать у регистратора домена —
   скопируйте их в личный кабинет регистратора (обычно достаточно одной записи CNAME).
4. Через 10–60 минут домен заработает, HTTPS-сертификат Render выпустит сам, бесплатно.

## Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| Деплой падает с ошибкой | Откройте вкладку **Logs** в Render — там текст ошибки. Частая причина: Start Command не `npm start` |
| Сайт открывается, но «Заявка не отправляется» | Смотрите Logs: чаще всего это нехватка прав на запись в папку данных. Проверьте `DATA_DIR` и наличие диска |
| Заявки пропали после обновления | Бесплатный тариф без диска. Перейдите на Starter + диск, иначе данные будут теряться |
| Первое открытие долгое (30–60 с) | Это «сон» бесплатного тарифа — нормально для Free, лечится платным тарифом |
| Фото не загружаются | Размер фото до 12 МБ, форматы JPG, PNG, WEBP, GIF, AVIF, SVG |

## Другие способы размещения

* **Railway.app** — в проекте есть `Dockerfile`, Railway соберёт его сам; удобно,
  но бесплатный лимит быстро заканчивается.
* **Свой VPS** (Timeweb, Beget, Selectel — примерно 200–500 ₽/мес): полностью под вашим
  контролем, домен и HTTPS настраиваются один раз. Запуск: `npm start`, папка `data/`
  остаётся на сервере.
* **Сайт на своём компьютере + бесплатный туннель** (Cloudflare Tunnel): сайт работает
  на вашем ПК, а в интернет отдаётся бесплатный адрес. Данные точно никуда не денутся,
  но компьютер должен быть включён, а адрес при перезапуске меняется.
